Codex: Phase 4 — синхронный packet-level тест

Предыдущий Phase 3 был неубедительным только из-за несинхронизированного времени попыток. В одном 60-секундном capture не было пакетов от CLIENT_IP, но Codex не смог подтвердить, что VPN и SSH попытки точно произошли во время этого окна. Теперь нужен один синхронный тест без неоднозначности.

Что уже известно

VPS:
- Ubuntu 24.04 LTS
- VPS IPv4: 206.245.129.65
- eth0 работает
- исходящий интернет работает
- SSH запущен
- Fail2ban не установлен

AmneziaWG:
- контейнер amnezia-awg запущен
- wg0 поднят
- VPN слушает UDP 32296
- Docker публикует UDP 32296
- UFW разрешает входящий VPN-порт
- legacy AmneziaWG 1.x
- другие клиенты имеют успешные handshakes

Проблемный клиент:
- CLIENT_IP=178.178.242.236

Phase 3:
- в читаемом 60-секундном capture не было ни TCP:22, ни UDP:32296 от 178.178.242.236
- client-specific UFW/SSH записей тоже не было
- handshakes/transfer counters для peer, ранее ассоциированных с этим IP, не изменились
- но попытки пользователя НЕ были подтверждены как происходившие внутри capture window
- поэтому причина пока не доказана

Цель

Сделать один синхронный 90-секундный capture ВСЕГО трафика от CLIENT_IP 178.178.242.236, а не только 22/32296.

Пользователь после сообщения READY выполнит подряд:
1) ping VPS
2) SSH к VPS
3) AmneziaWG

Это позволит отделить:
- полную недоступность IP/маршрута
- выборочную фильтрацию TCP/UDP
- проблему именно AmneziaWG

Ограничения

ТОЛЬКО read-only.
Не устанавливать пакеты.
Не менять firewall.
Не менять маршруты.
Не перезапускать VPS, Docker, SSH или amnezia-awg.
Не редактировать конфиги.
Не выводить payload пакетов.
Не раскрывать ключи/PSK/пароли/токены.

Точный порядок

1. Убедись, что tcpdump доступен. Если нет — НЕ устанавливай.

2. Запусти ровно один capture:

timeout 90 tcpdump -ni any "host 178.178.242.236" -tttt -nn -vv -l

Не используй -X или -A.
Не сохраняй pcap без необходимости.

3. СРАЗУ после фактического запуска tcpdump напиши пользователю:

READY

и больше ничего не выполняй, что может задержать тест.

4. После READY пользователь из сети 178.178.242.236 выполнит именно в этом порядке:

TEST 1 — ICMP:
ping -c 4 206.245.129.65
(если устройство/ОС не позволяет ping — сообщит об этом)

TEST 2 — SSH:
попытка SSH к 206.245.129.65:22 примерно 10 секунд

TEST 3 — VPN:
попытка подключения AmneziaWG примерно 15 секунд

5. После этого пользователь напишет:
DONE

6. Дождись завершения capture либо безопасно останови его после DONE, затем анализируй.

Что анализировать

Для CLIENT_IP 178.178.242.236:

ICMP:
- пришли ли echo request
- были ли echo reply от VPS

SSH:
- пришёл ли TCP SYN на 22
- был ли SYN-ACK
- дошло ли соединение до sshd
- были ли RST/timeout/firewall drops

VPN:
- пришли ли UDP-пакеты на 32296
- уходили ли UDP-ответы
- обновился ли latest handshake peer
- изменились ли RX/TX transfer counters
- были ли firewall drops

Также проверь journal/UFW только за точное тестовое окно и только для CLIENT_IP.

Интерпретация

CASE A:
Вообще НЕТ ни ICMP, ни TCP, ни UDP от 178.178.242.236.
=> трафик не достигает VPS.
=> локальная причина VPS маловероятна.
=> вероятен внешний маршрут/фильтрация IP/подсети либо проблема исходной сети.
=> не приписывать автоматически конкретному органу/оператору без дополнительных данных.

CASE B:
ICMP приходит, но TCP22 и UDP32296 нет.
=> IP достигаем, но есть selective filtering транспортных протоколов/портов.

CASE C:
ICMP и TCP22 приходят, UDP32296 нет.
=> очень сильный признак фильтрации UDP/порта/VPN-трафика, а не всего IP.

CASE D:
UDP32296 приходит, но handshake не обновляется.
=> проблема ближе к legacy AmneziaWG/сигнатуре/клиентской конфигурации.

CASE E:
Handshake обновляется, но VPN не работает.
=> смотреть NAT/forwarding/return path.

CASE F:
Все три теста доходят.
=> проблема нестабильная; повторить с другой российской сетью/оператором.

Финальный отчёт

A. Был ли тест синхронизирован и подтверждён пользователем: да/нет.
B. ICMP: request/reply.
C. SSH: SYN/SYN-ACK/sshd.
D. VPN: UDP in/out, handshake, transfer counters.
E. Firewall drops для CLIENT_IP: да/нет.
F. Где именно исчезает трафик.
G. Один следующий безопасный шаг.

Пока не менять IP, не менять порт и не мигрировать AmneziaWG.
Сначала нужен этот чистый синхронный результат.

Критично: после READY пользователь должен выполнить все три попытки сразу, а затем написать DONE. Только после этого делай вывод.
